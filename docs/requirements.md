# Бизнес-требования

## Цель
Автоматизировать публикацию товаров-забегов в WooCommerce на основе данных из Google Sheets, включая генерацию описаний и переводы, чтобы снизить ручной труд и ускорить выпуск контента.

## Источники данных
- Google Sheets: основная таблица с данными о забегах.
- Внешние источники: сайты организаторов и регламенты (PDF/HTML) для извлечения текста.

## Ключевые сценарии
- Система обрабатывает строки со статусами `Revised (incomplete)` и `Revised (complete)`.
- Для `Revised (incomplete)` генерируются поля `ORG INFO`, `SUMMARY`, `BENEFITS`, `FAQ` (EN/PT), затем публикуется карточка события, сохраняется baseline hash страницы `WEBSITE`, статус меняется на `Published (incomplete)`.
- Для `Published (incomplete)` ежедневно выполняется мониторинг изменений `WEBSITE` по сравнению hash (с нормализацией HTML); при изменениях отправляется уведомление в Telegram.
- Для `Revised (complete)` генерируется контент через OpenAI (описание, преимущества, информация об организаторе, FAQ), после чего данные обновляются в WordPress по `WP PRODUCT ID EN/PT`, а при отсутствии ID создаются новые товары.
- Опционально генерируется изображение и загружается в WordPress.
- Создается или обновляется variable-продукт в WooCommerce, настраиваются категории, атрибуты и вариации.
- Вариации синхронизируются по ID (`WP VARIATION ID EN`, `WP VARIATION ID PT`): существующие обновляются, новые создаются, отсутствующие в таблице удаляются из WooCommerce.
- Создается или обновляется английский перевод товара через WPML API, при этом основной товар — португальский.
- В Google Sheets обновляется статус строки и дополнительные поля результата.
- Отдельный ручной recovery-сценарий восстанавливает `WP PRODUCT ID EN/PT` и `WP VARIATION ID EN/PT` для старых опубликованных карточек, где эти значения не были записаны в Google Sheets.

## Выходные данные
- Товары WooCommerce с вариациями и атрибутами.
- Переведенные товары (EN) с привязкой к оригиналу PT.
- Обновления в Google Sheets (статус, дополнительные поля, `WP PRODUCT ID EN`, `WP PRODUCT ID PT`, `WP VARIATION ID EN`, `WP VARIATION ID PT`, hash-поля мониторинга).
- Уведомления в Telegram о различиях страницы `WEBSITE`.

## Ограничения и допущения
- Все секреты и настройки берутся из переменных окружения.
- Модели OpenAI, уровень размышления, температура и пути к системным промптам задаются через `.env`.
- Доступ к Google Sheets обеспечивается через сервисный аккаунт.
- WordPress должен иметь активные WooCommerce, WPML и JWT Auth плагины.
- Recovery-сценарий консервативен: не пишет ID при неоднозначном совпадении, провале валидации товара, конфликте даты/WEBSITE или неуникальном ключе вариации.
- Приоритет восстановления product ID: прямой ID из `LINK RACEFINDER`, ID из публичной страницы/shortlink/JSON, PT-перевод через `hreflang`, поиск по ACF `event_ticket_url`, затем составной fallback по названию, дате, городу и категориям при явной валидации.
- Вариации сопоставляются по нормализованному ключу атрибутов EN/PT, а не по названию вариации.
- Recovery-сценарий может формировать CSV-отчет с найденными ID, источниками сопоставления и причинами ручной проверки.

## Нефункциональные требования
- Работа в Docker без локального окружения.
- Повторные попытки при временных сетевых ошибках к Google Sheets и WooCommerce.
- Логирование ключевых этапов обработки.

Telegram-отчёт WEBSITE должен оставаться коротким при любом количестве изменений:
все изменения входят в счётчик, первые 10 — в краткий список, полный список
мероприятий доступен по ссылке на RACES. Полные WEBSITE в сообщение не добавляются.

Пустые необязательные поля (совместимость 18.11.2026): цена и даты мероприятия могут отсутствовать. Пустая цена передаётся как неизвестная, явный 0 — как бесплатное участие; непустые цены и даты проверяются. Пустые TEAM/TYPE/LICENSE сохраняются без подстановки значений. Пустые REGISTRATION DEADLINE и PRICE CHANGES при повторной обработке не очищают сохранённые значения сайта. Проверки ID, дублей, принадлежности и языков атрибутов остаются обязательными.

- Все три новые языковые карточки должны быть Variable с согласованным диапазоном цен и полным списком вариантов; для PRICE CHANGES проверяется действующий этап, будущие этапы преждевременно не применяются. Неизвестная цена не означает бесплатное участие.

Каждый глобальный атрибут вариации и значение по умолчанию должны ссылаться на термин языка родительской карточки, назначенный этому товару. Суффикс slug и отображаемый перевод WCML не являются доказательством языка. При восстановлении старых карточек сохраняются языковые версии, ID, цены, комиссии, остатки, контент и статусы; отсутствующие языковые записи получают прежние отображаемые подписи.

По явному запросу разрешено исправление терминов прошедших черновиков и корзины с сохранением всех языковых версий, статусов и метаданных восстановления. Обычный импорт и аудит актуальных событий не расширяют свою область на архив автоматически.

Отсутствие описания и одинаковые варианты участия не препятствуют созданию черновика. Одинаковые строки не объединяются и не удаляются автоматически. Языковые поля остаются структурно проверяемыми; если текст есть, его перевод не должен пропадать. Каждое расписание цены относится к ID своей строки.


Дистанция сохраняется последним атрибутом в PT/EN/ES; остальные атрибуты сохраняют относительный порядок. Позиции родителя задаются явно и проверяются после импорта. Для существующих карточек `wordpress/tools/distance-last.php` поддерживает аудит, адресное исправление с исходниками и повторную сверку: меняется только `_product_attributes`, без сохранения товаров и вариантов через WooCommerce. DEV и тема не затрагиваются.


Изменения общих значений WordPress/WPML журналируются модулем `rf-import-term-audit.php` в приватном каталоге `/home/developer/racefinder-validation/term-audit` (ежедневные JSONL, права 0600): пользователь, канал CLI/REST/админка, путь без query string, стек вызовов, записи до/после. Тела запросов, токены и IP не записываются. Прямые внешние SQL-операции не проходят через хуки WordPress; расхождения критических записей выявляются контрольным снимком `baseline.json` перед импортом. Изменение этого файла — отдельная операция восстановления, не автоматическое принятие нового состояния.

Создание терминов использует исходные записи WPML, явный языковой контекст и транзакцию; существующие привязки группы не могут незаметно заменяться новым переводом. Проверяются также подписи известных Walking/Road running, включая случаи, когда WPML ошибочно помечает испанское слово португальским. При нарушении запись отклоняется с конкретной ошибкой, без новых требований к пустым полям таблицы. Восстановление по исходным ID: `wordpress/tools/recover-term-dictionary.php`; исправление исторических ссылок только затронутых семейств: `plan-term-family-recovery.php`. Исходники карточек, цены, комиссии, ID и состав языков сохраняются. DEV и тема не изменяются.
